# SmolVLA原理、数据、微调与部署

> 本文以Hugging Face于2025-06-03发布的SmolVLA介绍和LeRobot公开资料为主。官方实验结果只适用于其数据、机器人和评测设置，不能直接外推到其他机械臂。

## 1. SmolVLA是什么

SmolVLA是一个约450M参数的开源视觉-语言-动作模型。它接收多相机图像、自然语言任务和机器人状态，输出连续的未来动作序列。

```text
RGB图像 + 任务指令 + observation.state
                   ↓
              SmolVLM2主干
                   ↓
             多模态上下文特征
                   ↓
        Flow Matching动作专家
                   ↓
          Action Chunk动作序列
```

它的意义不是“最小模型一定最好”，而是把公开数据、训练代码、微调和部署放进LeRobot生态，降低VLA实验门槛。

## 2. 两个核心组件

### 2.1 视觉语言主干

SmolVLA使用SmolVLM2处理多相机图像与语言。机器人状态通过线性层投影成与语言标记兼容的表示。官方为降低时延采取了减少视觉标记、使用中间层特征等设计。

### 2.2 Flow Matching动作专家

动作专家不是输出一段自然语言，而是生成连续动作块。训练时给真实动作轨迹加噪声，让模型学习把噪声轨迹逐步修正回合理动作。

```text
训练：真实动作 + 噪声 → 预测修正方向
推理：随机噪声 → 多步修正 → 连续动作块
```

它适合连续控制，但最终输出仍必须通过Robot Adapter转换成目标控制器认可的单位、坐标系和命令格式。

## 3. 数据集必须符合SmolVLA要求吗

是，但“符合要求”不等于原始数据必须一开始就长得完全一样。建议保留两层：

```text
Raw Data：相机原视频、关节日志、控制命令、标定和版本
    ↓ 清洗、对齐、语义转换
Canonical Data：统一字段、单位、时间轴和动作语义
    ↓ 导出
LeRobotDataset：供SmolVLA训练
```

一个训练episode至少要能同步表达：

- 一路或多路相机图像；
- `observation.state`，如关节角、夹爪状态或末端状态；
- 与每一时刻对应的`action`；
- 自然语言任务描述；
- 时间戳、帧序号和episode边界；
- 推荐增加成功/失败、操作者、机器人和控制器版本。

仅有“图像 + 指令”通常不足以监督低层动作。训练需要知道当时机器人实际执行了什么。

## 4. 官方社区数据如何处理

官方介绍称，SmolVLA预训练数据来自LeRobot社区数据。其公开流程强调：

1. 根据视觉质量、帧数和任务覆盖筛选数据；
2. 人工审核；
3. 用视觉语言模型清洗缺失或含糊的任务描述；
4. 将不一致的相机名称映射到标准视角；
5. 将所用SO100数据统一到30 FPS。

这说明机器人数据Scaling的核心不是简单堆帧数。任务描述、视角、动作语义和时间同步不统一，会直接降低可用性。

## 5. 微调还是从头训练

一般优先微调预训练模型：

```bash
python lerobot/scripts/train.py \
  --policy.path=lerobot/smolvla_base \
  --dataset.repo_id=<你的数据集> \
  --batch_size=64 \
  --steps=<根据验证集和资源确定>
```

从架构初始化训练则使用`--policy.type=smolvla`。这里的“从头训练”仍可能使用预训练VLM组件，不等于所有参数完全随机初始化。

选择建议：

- 同类机械臂、数据较少、窄任务：优先微调；
- 动作维度相同但语义不同：先做Adapter和归一化，不能直接混合；
- 机器人形态差异较大：考虑共享视觉语言主干，使用机器人专属动作头；
- 数据和算力不足：不要从头训练完整VLA。

## 6. 最小微调闭环

1. 先采集3至5条轨迹检查图像、状态和动作是否对齐；
2. 固定相机、标定、控制频率和动作语义；
3. 再采集约几十条高质量示范作为起点；
4. 按物体、位置和场景划分训练/验证集，不能随机拆帧；
5. 微调并检查损失、离线动作误差和可视化轨迹；
6. 先仿真或低速空载，再进入受控真机；
7. 记录失败、人工接管和结果标签，再训练。

“约50个episode”只能作为某些窄任务的起点经验，不是保证成功的行业标准。

## 7. 跨机器人使用时要检查什么

即使动作都是7维，也要逐项核对：

- 关节空间还是末端空间；
- 绝对值、增量、速度还是力矩；
- 基座、相机或工具坐标系；
- 米、厘米、弧度等单位；
- 欧拉角、四元数等旋转表达；
- 夹爪0/1的方向和实际行程；
- 控制频率、时延和动作块长度；
- 每种机器人的归一化统计。

必要时增加`embodiment_id`，并为不同机器人维护独立Adapter或动作头。

## 8. 官方结果怎样正确解读

官方介绍报告：社区预训练和多任务微调改善了其SO100/SO101实验；异步模式在成功率相近时缩短任务时间并提高固定窗口吞吐量。这证明该路线在特定实验中有效，但不证明：

- 换一台机械臂仍有相同成功率；
- 所有任务都能提升30%；
- 异步一定带来2倍吞吐；
- CPU运行就能满足任意控制频率；
- 无需目标机器人数据即可部署。
