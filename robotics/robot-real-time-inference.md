# 机器人实时推理：同步、异步、Action Chunk与安全Harness

## 1. 一句话理解

- **同步推理**：机器人想完再动，执行结束后再等待下一次推理。
- **异步推理**：机器人执行当前动作时，模型同时计算后续动作。

异步说的是模型推理和机器人执行的调度方式，不等于模型本身推理更快，也不等于输入一定包含音频。

## 2. 同步模式

```text
采集图像和状态
      ↓
等待模型生成动作块
      ↓
机器人执行动作块
      ↓
再采集、再等待
```

优点是实现简单，新动作与当前观测关系明确。缺点是模型推理期间机器人可能暂停，长动作块执行期间又无法及时利用新观测。

## 3. 异步模式

```text
推理线程：最新观测 → 策略服务器 → 新动作块
                                  ↓
                               动作队列
                                  ↓
控制线程：持续取出动作 → Robot Adapter → 控制器
```

机器人执行动作块A时，推理服务器计算动作块B。只要B在队列耗尽前到达，控制循环就不必停下来等模型。

## 4. Action Chunk是什么

VLA常常一次预测未来多个控制时刻：

```text
[a1, a2, a3, ... aN]
```

如果控制频率是20 Hz、动作块包含20个动作，那么它覆盖约1秒。这只是示例，不是SmolVLA的固定参数。

动作块带来两种相反需求：

- 块长一些：模型调用少，动作较连续；
- 块短一些：能更频繁使用新观测，反应更及时。

因此不能只追求更长的chunk。

## 5. SmolVLA异步栈的关键机制

官方介绍给出的核心思路包括：

1. **早期触发**：动作队列下降到阈值时提前请求下一块；
2. **解耦线程**：控制循环不被远程推理阻塞；
3. **片段融合**：处理连续动作块的重叠区域，减少边界抖动；
4. **策略服务器**：模型可以运行在远程GPU上，机器人侧负责观测发送和动作消费。

文中的70%是机制示例，不应当作所有机器人的最佳阈值。

## 6. 异步为什么可能更快

同步：

```text
推理 ███  执行 █████  推理 ███  执行 █████
```

异步：

```text
推理     ███       ███       ███
执行 █████████████████████████████
```

异步主要通过重叠推理和执行来隐藏等待时间。官方SmolVLA实验在特定任务上报告任务时间约快30%、固定窗口完成数量增加，但这是实验结论，不是通用性能承诺。

## 7. 异步也可能执行“过时动作”

这是异步最容易被忽略的风险。假设机器人正在执行旧动作块，物体突然被移走：

- 队列太长：机器人会继续执行旧计划；
- 直接替换：动作可能突然跳变；
- 一直追加：动作平滑，但响应越来越滞后；
- 融合新旧块：通常更平衡，但需要时间戳和重叠策略。

所以“异步更快”不等于“任何情况下都更灵敏”。必须同时管理动作新鲜度、连续性和安全性。

## 8. RTC与普通异步的关系

RTC（Real-Time Chunking）关注新动作块如何与已经承诺或正在执行的动作衔接。概念上，它不是简单地把新块放到旧块后面，而是在不破坏近期动作连续性的前提下，让更远期动作吸收最新观测。

普通异步解决“推理和执行能否并行”；RTC进一步解决“新旧动作块如何实时协调”。具体实现与参数应以当前LeRobot版本文档为准。

## 9. 本地安全Harness必须做什么

即使模型运行在远程GPU，本地机器人侧也应保留：

- 关节、速度、加速度和工作空间限位；
- 动作格式、单位和NaN检查；
- 观测与动作时间戳；
- 最大队列长度与动作过期丢弃；
- 推理和网络超时；
- 超时时保持或安全停止，不能无限重复旧动作；
- 碰撞检测、急停和人工接管；
- 完整保存观测、预测、实际动作和执行结果。

推荐运行链路：

```text
相机/状态 → 观测时间戳 → 异步策略服务
                              ↓
                    动作块 + 生成时间戳
                              ↓
           新鲜度检查 → 融合 → 限位 → 控制器
                              ↓
                      结果日志与急停
```

## 10. 如何比较同步和异步

不能只看平均推理时间，至少记录：

- 任务成功率；
- 完成时间和固定窗口吞吐量；
- 控制循环实际频率；
- 队列长度与队列耗尽次数；
- 观测到动作执行的端到端延迟；
- 动作年龄和被丢弃的旧动作数；
- 抖动、碰撞、急停和人工接管次数；
- 有无扰动时的恢复能力。
