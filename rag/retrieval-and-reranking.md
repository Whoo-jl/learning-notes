# RAG 检索中的粗排与精排

粗排和精排都是排序，但面对的集合和要解决的问题不同。**召回**从索引找出有可能相关的资料。**粗排**用成本较低的信号排序、融合并截出一批候选。**精排**在候选范围内重新判断问题与资料的关系，把更有用的证据排到前面。之后还要根据证据覆盖和上下文预算决定给生成模型看哪些片段。

有的系统把索引返回结果的过程称为“召回＋粗排”，有的把多路融合单列，还有产品把融合本身称为 rerank。看实现时先问两件事：**该步骤能从索引找到新资料吗？它是用已有分数和名次排序，还是重新读问题与候选来打分？**

```mermaid
flowchart LR
    Q["问题与检索范围"] --> S["多路召回"]
    S --> F["去重、粗排和融合"]
    F --> K["候选池"]
    K --> R["精排重新打分"]
    R --> E["选证据并组装上下文"]
    E --> G["生成答案与引用"]
```

## 一、先分清什么算有效证据

用一份虚构的报销制度举例。用户问“因公出差的费用最晚几天内提交，延期需要谁批准？”数据库里有四个片段。

| 片段 | 内容 | 对这个问题的作用 |
| --- | --- | --- |
| A | 出差报销必须附行程单和发票。 | 主题相同，回答的是材料要求。 |
| B | 因公出差的报销提交期限可延至费用发生后 60 天。 | 支撑期限。 |
| C | 差旅报销延期须经直属主管批准。 | 支撑审批条件。 |
| D | 超出普通报销期限的申请将退回。 | 语义相关，但没有给出差旅例外的期限或审批人。 |

这个问题至少需要 B 和 C。只找到 B，可以回答期限，不能确认审批人。A 里命中了“出差报销”，也并不构成答案。有效证据通常要能支撑所问对象、属性和适用条件。判断“相关”时，训练或评估标签应区分直接证据、补充材料、主题相似但不能作答，以及过期或范围不符的材料。

## 二、召回和第一轮排序怎么做

### 1. 检索范围、路由与查询改写

检索前先决定去哪找。权限、空间、文档范围、明确指定的版本或生效日期，可以作为可验证的过滤条件。对问题里不明确的对象，则应保留适当范围，避免猜错过滤条件把证据排除。只在拿到候选后才过滤，可能因为错误范围先占满 Top K 而拿不到足够的合格结果。前置过滤、索引过滤和后置过滤的具体语义因引擎而异。

查询理解可以保留原问，同时做同义词扩展、指代补全和多查询拆分。例如，把“最晚几天，谁批准”拆成“出差报销提交期限”和“差旅报销延期审批人”，分别取候选。也可以路由到知识库、产品目录、结构化表或其他来源。HyDE 是另一种扩召回方法，先生成一段假想文档，把其向量作为检索线索，再找真实文档。改写和假想文档都可能引入新条件，应保留用户原意和查询来源，最终答案引用真实证据。 [Datawhale 查询改写与路由](https://github.com/datawhalechina/all-in-rag/blob/main/docs/chapter4/14_query_rewriting.md) · [HyDE](https://arxiv.org/abs/2212.10496)

### 2. 关键词、稀疏与稠密检索

| 方法 | 怎么从库里找候选 | 强项和局限 |
| --- | --- | --- |
| 关键词检索，例如 BM25 | 通过倒排索引找到包含查询词项的片段。BM25 的排序考虑词项稀有程度、词频饱和和文本长度。可叠加短语匹配、字段权重和同义词。 | 适合料号、术语、错误码、制度编号。依赖分词、大小写、符号和字段配置。严格标识符宜用精确字段匹配，避免被普通分词拆开。 |
| 学习式稀疏检索，例如 SPLADE | 模型把查询和文档映射到稀疏的词表权重，可扩展相关词项，并利用稀疏检索结构搜索。 | 能补一些词项表达差异，同时保留词项层信号。需要额外编码，索引大小、稀疏度和查询延迟要测。 |
| 稠密向量检索，例如 DPR 或双编码器 | 离线编码文档，在线编码查询，用余弦、点积或系统约定的距离搜索近邻。双编码器独立编码查询和文档，所以文档向量可以复用。 | 适合改写、同义和自然语言描述。语义相近的不同对象、数值、否定或版本可能被混在一起。 |
| 精确字段或结构化查询 | 直接按 ID、版本、日期、枚举等定位，或按表字段过滤和计算。 | 适合确定条件、筛选与聚合。数据缺字段或值不准时，应先解决数据质量。它也能作为混合检索的一路或限定范围。 |

[Datawhale 混合检索实现](https://github.com/datawhalechina/all-in-rag/blob/main/docs/chapter8/03_index_retrieval.md) · [SPLADE](https://arxiv.org/abs/2107.05720) · [DPR](https://arxiv.org/abs/2004.04906) · [Sentence Transformers 双编码器与精排](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)

**BM25 的两个常见旋钮。** `k1` 控制同一词多次出现后，额外词频的收益何时饱和。`b` 控制对文档长度的归一化程度。它们会受分块方式影响。把短 FAQ 和长章节放在同一索引时，需检查长度差异是否把词项相同的片段排得失衡。 [BM25 原始综述](https://www.staff.city.ac.uk/~sbrp622/papers/foundations_bm25_review.pdf)

**向量搜索深度和返回 K 要分开。** 精确近邻可以逐条计算距离。大库常用近似近邻搜索（ANN），例如 HNSW 图索引，以一部分搜索精度换延迟。`ef_search` 或 `num_candidates` 这类参数控制引擎内部探索深度，`k` 控制该路对外返回多少。量化索引有时会先多取一些候选，再用原始浮点向量复算距离。这个复算仍依据向量距离，可以改善近邻排序。它不等于 Cross-Encoder 对问题与候选正文重打分。定位向量路漏召回时，可在小样本用同一 embedding 做精确近邻对照，区分索引近似带来的损失和模型本身的匹配误差。 [Elastic kNN 参数](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-knn-query) · [Elastic 向量搜索优化](https://www.elastic.co/docs/solutions/search/vector/knn/optimize-performance-accuracy)

### 3. 多路候选怎样融合

混合检索通常把关键词、稠密向量、不同查询改写或不同数据源的候选合起来。先以稳定的 chunk ID 或文档 ID 认出同一结果，保留其各路名次和分数，再形成一个候选池。统一到文档级还是块级很重要。把同一文档的所有块过早合成一条，可能把同一文档里互补的 B 和 C 一起折掉。

- **并集、配额和轮询。** 每路保留一定名额，或按路交替取结果。做法简单，能保证重要通道有最低候选份额，但会消耗预算在弱通道上。多查询或多来源差异很大时可作为基线。
- **按分数融合。** 先把各路分数变换到可比较范围，再加权，例如 `α × 向量分 + (1 − α) × 关键词分`。分数法保留“第一名领先多少”这类信息。原始 BM25 分、余弦分和模型 logit 的尺度不同，直接相加会让数值大的通道占优势。归一化也受候选窗口、异常值和缺失分处理影响，权重需要验证。Weaviate 的 relative score fusion 是这一类。
- **按名次融合。** RRF（倒数排名融合）给每路的第 `r` 名贡献 `1/(c+r)`，再加总。加权变体可乘各路权重。某路没命中就没有该路贡献。它便于融合不同分数尺度，但忽略了名次之间的实际分差。相近的改写路线如果很多，也可能放大重复的投票信号。
- **规则或学习排序。** 在候选集合上叠加标题匹配、精确术语、字段分、来源和时效等特征。规则容易解释。需要学习组合时，可用逻辑模型或 LambdaMART 等学习排序方法。训练要覆盖线上问题和困难负例，若使用点击信号还应考虑位置偏差。轻量学习排序可以放粗排，较重的特征也可以放精排。

[RRF 原论文](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf) · [混合检索融合函数对照](https://arxiv.org/abs/2210.11934) · [Weaviate 两种融合策略](https://docs.weaviate.io/weaviate/concepts/search/hybrid-search) · [LambdaMART 技术报告](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/MSR-TR-2010-82.pdf)

**手算一遍 RRF。** 假设关键词路返回 `A → B → C`，向量路返回 `B → D → C`。两路等权，平滑常数 `c = 60`。

| 片段 | 关键词名次 | 向量名次 | 融合分 |
| --- | ---: | ---: | ---: |
| B | 2 | 1 | 1/62 + 1/61 ≈ 0.03252 |
| C | 3 | 3 | 1/63 + 1/63 ≈ 0.03175 |
| A | 1 | — | 1/61 ≈ 0.01639 |
| D | — | 2 | 1/62 ≈ 0.01613 |

B 和 C 排在前面，是因为两路都找到了它们。RRF 自己并未判断“60 天”是否正确。`c` 越大，同一路内前几名的贡献差距相对越小。它是**公式常数**，和每路取多少、融合后留多少的 Top K 是不同参数。要是两路都只取前 2，C 就无法进入融合或后续精排。 [Elastic RRF 参数与窗口](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

粗排完成后截出候选池。多路返回各 50 条，若有 30 个 ID 重合，去重后是 70 条，未必全部送精排。系统可以进一步限到前 40 条。每次截断都可能丢证据，排查时要记录候选在哪个阶段消失。


## 三、精排有哪些实现

### 1. Cross-Encoder 联合打分

Cross-Encoder 把问题与一个候选的正文一起送进模型。模型可以同时看到问题的“延期”和候选的“主管批准”，也能区分“出差报销材料”和“出差报销期限”。这比先独立压成两个向量、再算一次相似度，有更多机会判断对象、动作、否定和限制条件。通常为每个问题与候选组合算一个相关性分，随后排序。文档表示不能像双编码器的单向量一样提前为所有问题算好，因此一般只在有限候选池上运行。批处理可以减少调用开销，实际负载仍取决于候选数、总 token 数、模型大小和并发。

精排看到的正文要和任务匹配。把标题、章节、产品名、版本和必要表头一起送入，通常比裸句更容易判断指代。太长时可能发生截断。若答案总在后半部分，应先检查模型或 API 实际读到的文本，必要时按证据粒度切短、按段分别打分。以一个文档内所有段的最高分代表整份文档，适合“是否包含某条证据”，但会丢掉第二条互补证据，也可能偏向段数更多的长文档。保存命中片段 ID 和原文区间，有助于后续引用。 [Sentence Transformers](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html) · [BERT passage reranking](https://arxiv.org/abs/1901.04085) · [Cohere Rerank 输入与截断](https://docs.cohere.com/reference/rerank) · [BGE Reranker 中文项目示例](https://bge-model.com/tutorial/5_Reranking/5.2.html)

### 2. 多向量与晚交互

ColBERT 分别编码查询和文档，但保留多条 token 向量。打分时，对查询的每个 token 找到文档中最匹配的 token，再把这些最大相似度加总，这就是 MaxSim。这样保留了比单向量更细的匹配信息，又允许离线缓存文档的多向量。代价是索引体积和比较开销更大，需要专门的压缩或检索实现。它既可在候选池上做重排，也可构建支持多向量搜索的召回层，具体取决于部署。**晚交互**描述查询和文档何时匹配。[分块笔记](chunking-strategies.md)中的 **Late Chunking** 则描述如何从长文本的 token 表示生成块向量。 [ColBERT](https://arxiv.org/abs/2004.12832) · [ColBERTv2](https://arxiv.org/abs/2112.01488) · [Datawhale 高级检索教程](https://github.com/datawhalechina/all-in-rag/blob/main/docs/chapter4/15_advanced_retrieval_techniques.md)

### 3. 用 LLM 排候选

| 比较单位 | 如何工作 | 主要取舍 |
| --- | --- | --- |
| Pointwise，逐条判断 | 每次看一个候选，输出是否支撑问题或给出相关性分，再排序。Cross-Encoder 的常见推理方式也属于逐条打分。 | 可以独立批处理，候选之间不必共同占用窗口。跨候选的分数可能不稳定。 |
| Pairwise，两两比较 | 每次输入两个候选，请模型选更能回答问题的一个，再用比较排序、分轮淘汰等方式生成排序。 | 容易表达“哪条更好”，直接比所有对时成本随候选数平方增长。减少比较次数会带来排序策略上的取舍，且需处理顺序偏差与比较不一致。 |
| Listwise，按列表排序 | 把一组候选和稳定 ID 交给模型，要求返回重排后的 ID 列表。候选太多时，可用滑动窗口或分组。 | 能利用同组候选的相对关系，但受输入顺序、上下文预算和跨组结果拼接影响。应检查漏 ID、重复 ID 和虚构 ID。 |

这些描述的是比较方式，可以用于训练目标，也可以用于推理接口，两者并不要求相同。例如，一个按成对偏好训练的模型，推理时仍可以独立打分。通用 LLM 能把业务规则直接写进提示词，但请求长度、调用费用和输出稳定性要实测。生产上可先用较轻模型处理较大候选池，再只对少量疑难候选做 LLM 复核。 [RankGPT](https://aclanthology.org/2023.emnlp-main.923/) · [Pairwise Ranking Prompting](https://arxiv.org/abs/2306.17563)

### 4. 模型分、业务特征和阈值

有的系统直接按精排模型分排序，有的保留关键词命中、原检索分、文档来源等信号并重新组合。对错误码、产品型号等查询，精确字段命中仍然重要。对规则和制度，生效版次应由过滤条件控制。把旧版仅当成低一点的分数，可能让它在没有新版证据时仍被选中。学习排序也可以在这一层整合模型分和业务特征。

**排序分、阈值和置信度要分别理解。** 模型分可以是 logit、相似度、归一化值或服务定义的区间。两个模型给出的 `0.8` 没有统一含义。即使对 logit 做 sigmoid 映射到 0–1，分数也不能直接解释为“答案有 80% 概率正确”。阈值应在本地标注集上根据误收、漏召回和拒答需求来选，明确比较的是原始模型分还是复合分。模型、语言、查询类型、截断方式变了，应复测。阈值过滤后可以少于目标 K，必要时返回部分证据或证据不足。 [BGE 分数映射](https://bge-model.com/tutorial/5_Reranking/5.2.html) · [Cohere 分数与阈值说明](https://docs.cohere.com/docs/reranking-best-practices)

## 四、排名靠前之后还要选证据

逐条打高分，不能保证前几条合起来回答完整。若前 3 条都是 B 的重复转述，取前 3 条仍缺审批人。这里要从“单条相关性”转向“证据集合的覆盖”。

- **去重和来源聚合。** 按稳定 ID、原文区间或内容重复去重。多个子块指向同一父块，可合并父正文并保留各自的证据位置。同一文档里 B 和 C 有不同作用，不能仅按文档 ID 丢掉其中一条。
- **多样性和覆盖。** MMR（最大边际相关性）每轮在候选中选择同时相关、与已选结果重复较少的一条，典型形式为 `λ × 相关性 − (1 − λ) × 与已选结果的最大相似度`。`λ` 越大越强调相关性。MMR 有助于减少重复，但对多个明确子问题，还可以单独保留每个子问题的证据，再合并去重。过度追求多样性也可能挤掉关键的同主题条款。
- **补全上下文。** 按需补同一版本的标题、表头、邻句或父块。给生成模型的实际预算应按 token 计算。保留原文、位置和文档版本。遇到冲突时核对适用范围和生效版本。找不到审批证据时，只回答能证实的期限，并明确审批人尚无依据。

[MMR 原始研究](https://aclanthology.org/X98-1025/) · [句子窗口和父子块](chunking-strategies.md)

## 五、Top K 到底在数什么

| 参数所在层 | 数的是 | 增大后主要影响 |
| --- | --- | --- |
| 索引内部搜索深度 | 引擎探索的近邻、候选或重算数量，可能按分片计 | 近似索引的命中与搜索开销 |
| 各路召回数 | 关键词、向量、不同改写各自返回的条数 | 能进入融合的证据范围 |
| 融合窗口及融合后的候选数 | 每路参与融合的名次窗口，以及去重后保留的条数 | 多路证据是否能在进入精排前留下 |
| 精排输入数与模型返回数 | 真正给模型评分的条数，以及希望拿回多少排序结果 | 相关证据进入前排的机会、推理延迟和成本 |
| 最终上下文数量与 token 预算 | 去重、合并、扩展后的证据条目和实际文本量 | 多证据覆盖、冗余、生成成本 |

同样叫 `top_k` 的字段可能在不同层。RRF 的 `rank_constant` 则不是条数。一般先保证融合候选覆盖率，再在能满足延迟的范围内找精排输入深度。精排后再按证据和 token 预算选取，输出不必填满。块大小变化时也要复测。前 10 个 200-token 块和前 10 个 800-token 块的上下文开销不同。

## 六、怎么评估和定位问题

给问题标注能支撑答案的原文证据，并标记对象、版本、数值和适用条件。多条件题分开标每项必需证据。再加入容易混淆的负例，例如主题相同但回答另一属性、只符合部分条件、近似型号、旧版制度和完全无答案的问题。切分变化时，仍用原文区间、表格行或文件页做共同标签。

| 评估位置 | 看什么 | 怎样解释 |
| --- | --- | --- |
| 各路召回、并集和融合后 | Hit@K、证据 Recall@K、全部必需证据覆盖率 | Hit@K 只问是否有至少一条相关证据。Recall@K 衡量标注证据找回的比例。多证据题还要看所有必需证据是否同时出现。对比每路、并集和融合窗口，可以定位遗漏发生在索引还是截断。 |
| 精排前后 | MRR@N、nDCG@N、关键证据在前 N 的覆盖 | MRR@N 取首条有效证据的名次倒数，前 N 没有则记 0，再对查询平均。nDCG@N 按分级相关性给收益，越靠后折扣越多，再和理想排序比较。两者都不能替代多证据覆盖。 |
| 最终上下文与生成 | 证据覆盖、引用支持性、答案正确率、无答案拒答 | 正确片段进入精排不等于最后进了提示词。检查去重、父块展开、截断和引用映射。引用正确不仅要指对来源，还要能支撑回答里的事实。 |
| 性能和成本 | 候选数、精排输入 token、P50/P95 分阶段延迟、调用成本与回退率 | 关注真实文本长度和并发。批处理、缓存、模型降级或超时回退都可能改变线上分布。记录正常排序与回退排序，才能解释效果变化。 |

以虚构报销题为例，若粗排候选包含 B 和 C，而精排前 2 变成 B、A，首条证据排第一，MRR 仍是 1，但前 2 的证据召回只有 1/2，审批问题仍答不全。反过来，如果 C 在候选池中就不存在，纯重排无法把它排上来。后续父块或邻句若恰好补出了 C，那是**上下文回取**带来的增益，应单独记账。

实验可以分三步做。先固定语料、分块和查询，对比关键词、向量、混合检索，分别记录各路和融合后的证据覆盖。再**固定同一批候选**对比粗排顺序与精排顺序，测出模型本身的贡献。最后固定生成模型、提示词和上下文 token 预算，比较答案、引用与延迟。只对已含正例的候选做精排测试，会高估端到端表现。应另外保留原始召回失败的查询。 [Sentence Transformers 重排评估](https://www.sbert.net/docs/package_reference/cross_encoder/evaluation.html)

| 现象 | 优先排查 |
| --- | --- |
| 真实证据未进入任何一路 | 文档解析与切分、索引状态、权限和版本过滤、查询写法、关键词分析器、向量搜索深度 |
| 各路有证据，融合后消失 | ID 去重规则、路权重、每路窗口、融合后的截断 |
| 候选里有，精排后消失 | 模型实际输入是否截断、是否缺标题或字段、阈值和分数融合、模型是否理解业务近义项 |
| 精排前面有，答案没用上 | 上下文去重、父块补全、token 预算、引用映射和生成 |
| 好像有结果，但都答不上来 | 区分模型不可用时的回退与真正的低相关结果，核对阈值与拒答逻辑 |

对能通过唯一键直接定位的查询，可以走字段查找。对候选少、第一次排序已经可靠的任务，可以用对照实验判断是否需要再加模型。复杂问答更值得关注每项证据是否被找齐，而不是只追求第一名的分数。

## 七、回顾与问答

**一分钟怎么讲召回、粗排和精排？**

> 召回从索引里尽量找齐可能有用的资料。粗排用较低成本的信号排序，或者把关键词、向量等多路候选融合，再截出一个候选池。精排对这批候选重新判断问题与正文的关系，把能支撑答案的片段往前提。最后还要去重、补上下文并覆盖每个子问题。评估时先看关键证据是否进入候选，再看精排有没有把它排到可用位置，以及最终答案和引用是否正确。

**BM25 和 embedding 各自解决什么？** BM25 对明确词项、编号和术语有优势。Embedding 用语义相似度补不同表达。两路都可能误判，同一编号也可能有多个版本，所以还要用字段过滤和证据核对。

**RRF 和 Cross-Encoder 都在改排序，有什么差别？** RRF 用已有的名次把几路候选合成一张榜单。Cross-Encoder 会读问题和每条候选的内容，再产生一个相关性分。RRF 可以是精排的上游。具体项目即使把 RRF 函数命名为 rerank，也要看它是否调用了模型。

**向量搜索放大候选后再用原始向量复算，算精排吗？** 它属于向量检索的第二次打分。它改善的是近似或量化距离下的排序。如果要讲 RAG 的模型精排，应另外说明是否对问题与候选正文做了联合打分。

**精排能提高召回率吗？** 要说清楚是哪一层的召回率。对固定候选池，纯精排无法扩大池中已有的证据总量。但它能把池里靠后的有效片段提进输出前 N，因此可以提高最终 Recall@N。若同时触发重新检索，那是额外召回。

**K 越大越好吗？** 候选 K 大，有机会找回更多证据，也会增加融合与重排负载。最终 K 大，可能带回重复和干扰。通常用候选覆盖率、精排成本和生成 token 预算一起选值。

**怎样判断一个精排模型确实有效？** 在相同候选上比较重排前后，既看首条证据的名次，也看多个必需证据是否都进入前 N。再在相同上下文预算下验证答案与引用，并测额外延迟。保留无答案和难负例，避免只测容易的正例。
